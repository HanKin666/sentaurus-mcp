# 状态、失败诊断与实验打包

本页描述 `v0.1.0-alpha.3` 的功能，Python 包版本为 `0.1.0a3`。较早测试版的功能范围请查看其对应标签。

## 看哪一个状态

先调用 `get_experiment`。`state` 是持久化的执行记录，`observation` 是本次查询采集的证据。
查看 `collected_at`、Worker 租约时间、运行心跳和进程身份。心跳过期或进程丢失时，
不能继续仅凭数据库中的 `running` 宣称还在计算。查询不会自动杀进程、重新提交或把旧记录改成失败。

MCP 请求超时、心跳过期、求解器非零退出分别处理。客户端请求结束不触发墙钟限时杀任务。
独立 Worker 必须由操作者单独启动，任务不依赖 LLM 客户端保持连接。

## 失败后怎么查

调用 `diagnose_experiment(run_id)`，返回当前观测、失败阶段、退出码、错误和最多 12000 字节日志尾部。
许可证、收敛、输入路径和内存关键词只是诊断线索。退出码为零也不证明达到目标偏压、数值收敛或物理验收。
该接口不自动改变输入或重试。

创建实验时可在每个阶段声明 `expected_outputs`，例如：

```json
{"tool": "sdevice", "input_file": "device.cmd", "expected_outputs": ["drain.plt", "device.tdr"]}
```

进程执行状态和 `status.output_validation` 分开：退出码均为零时执行状态可为 `completed`，
但声明文件缺失时 `output_validation.status` 为 `missing`；未声明输出则为 `not_requested`。
`present` 仅表示文件存在，不检查文件内容、完整偏压范围或收敛，也不证明本阶段新生成了该文件。

新实验保留配置和工具可执行文件哈希，提交、派发及各阶段启动前再次核对。
旧实验没有这些指纹时保留原始状态，不能追认为已做同等审核。
运行档案记录每阶段开始/结束时间，并按固定间隔采样可见求解进程树的内存、线程和CPU时间。
这是采样观测值，短命子进程可能漏采，内存和线程数不是实际使用CPU核心数，也不构成资源利用率保证。

## 分别打包或一起打包

启用操作权限后，调用 `export_experiments`：

```json
{"run_ids": ["run_a"]}
```

```json
{"run_ids": ["run_a", "run_b", "run_c"]}
```

每次选择 1 至 20 个已完成或失败的实验。ZIP 保存于实验根目录下的 `_exports`，返回服务器文件路径、大小和 SHA-256。
客户端需要通过自己的文件传输功能取回该文件；返回路径并不代表已经下载到本机。

包内保留脚本、参数文件、原始结果及日志，并包含 `export.json` 和运行说明。
`export.json` 记录运行清单、输入哈希、执行命令、阶段状态、时间和每个归档文件的哈希。
输入变更、归档时文件变化、超出 512 MiB 或 10000 个文件时拒绝打包。
符号链接和目录链接不跟随，并在清单中披露。运行中的实验暂不打包，避免将尚未写完的结果当最终结果。

这是可追溯的原生批处理档案。它不会生成 SWB 工程树；恢复到另一台服务器后，需要核对安装版本、工具路径和许可证。
已有 SWB 工程的自动追加实验、TDR 解析、物理指标自动验收仍需单独实现和真实软件验证。

## 连接成功的含义

保存连接配置、端口协议可识别、SSH 认证通过、远端 MCP 就绪、Worker 在线和 Sentaurus 实际执行通过是不同阶段。
连接向导保存本地配置后，远端状态仍待验证。VNC 显示编号和 TCP 端口需要分别确认，不能把显示编号当作 SSH 端口。

## 验证边界

开发测试采用独立临时目录及 Python 合成任务，覆盖状态、失败、断开连接后继续执行和打包完整性。
这些测试不调用私人科研工作台，也不代表已经完成真实 Sentaurus、许可证或器件物理验收。
